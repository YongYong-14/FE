# Android 실제 블루투스와 GPS

기준일: 2026-11-11

## 1. 기기 등록과 연결

- 사용자가 Android 설정에서 페어링한 기기를 앱의 내 차 등록 화면에서 한 개 선택한다. 시연용 이어폰·스피커도 등록할 수 있다.
- 앱은 페어링·오디오 연결을 직접 수행하지 않는다. 기기 목록은 Android의 실제 등록 기기 목록이며 이름·MAC·종류를 기존 차량 API에 보낸다.
- 등록한 MAC 주소의 연결·해제만 주차 흐름에 반영한다. 다른 기기의 이벤트는 무시한다.
- 처음부터 연결이 안 된 기기를 등록한 것만으로 주차를 시작하지 않는다. 실제 연결 후 해제될 때 주차 추정을 생성한다.
- 재연결 시 기존 정책대로 진행 중인 위치 확인·분석을 취소한다. 같은 이벤트의 중복 수신은 한 번만 처리한다.
- 차량 오디오·이어폰·스피커의 초기 연결 상태는 A2DP/HFP/보청기/LE Audio 공개 API로 조회한다. 그 외 종류는 초기 상태를 알 수 없을 수 있으며 실제 ACL 연결 이벤트를 받은 뒤 상태를 표시한다.

## 2. 백그라운드 이벤트

- 로컬 Expo 모듈 `modules/vehicle-bluetooth`가 Android Bluetooth ACL 브로드캐스트를 받는다. 이벤트 시각과 최신 미처리 이벤트는 Android SharedPreferences에 보관한다.
- 다른 앱을 사용하거나 화면이 꺼진 동안에도 수신된 이벤트를 보관하고, 앱 복귀 시 주차 진행 상태에 반영한다. 앱을 강제로 앞으로 띄우지 않는다.
- 재연결이 마지막 이벤트라면 오래된 해제를 새 주차로 복원하지 않는다. 마지막 재연결 시각도 보관해 재연결 후 다시 해제됐을 때 이전 진행을 취소하고 새 주차로 처리한다. 계정·등록 차량 변경 및 로그아웃 시 추적 대상과 이전 이벤트를 지운다.
- Android 설정의 강제 중지, 제조사의 절전·앱 종료 정책, 재부팅 동안의 지속 수신은 보장하지 않는다. 단순히 앱이 안 보이는 상태와 강제 중지를 구분한다.
- 지속적인 블루투스 탐색·오디오 연결·위치 추적 서비스는 실행하지 않는다. 별도의 상시 알림을 추가하지 않는다.

## 3. 실제 위치

- 위치 권한과 휴대폰 위치 서비스가 켜져 있어야 한다. 앱은 위치·근처 기기 권한을 실제 Android 시스템 화면으로 요청한다.
- 연결 해제 순간에 위치 접근이 가능하면 최근 15초 내 측위를 보관하고, Android 11 이상에서는 최대 7초 동안 새 GPS 측위를 한 번 요청한다. 백그라운드에서는 위치 ‘항상 허용’ 권한이 있어야 이 요청을 시도한다.
- 저장한 측위는 동일한 해제 시각에 해당하는 주차에만 사용한다. 재연결·등록 변경 후 늦게 도착한 측위는 버린다. 보관된 측위가 없으면 위치 확인 화면에서 새 GPS를 요청한다. 재측정은 보관된 위치를 재사용하지 않는다.
- 새 GPS 조회는 `expo-location`을 사용하며 20초 초과·권한 거부·위치 서비스 꺼짐·정확도 미제공을 실패로 처리한다. 실패를 예시 위치로 대체하지 않는다.
- Android 역지오코딩의 시·군·구로 용인시 여부를 확인한다. 행정구역 조회 실패를 용인시로 간주하지 않는다. 현재 데이터의 경계 사각형으로 지원 지역을 판정하지 않는다.
- 정확도·보정 범위·타이머 기준은 기존 정책을 유지한다. 15m 이내 자동 확정, 15m 초과~50m 직접 확인, 50m 초과 직접 위치 지정, GPS 기준 200m 이내 보정이다.
- 지도 탭 현재 위치와 최근 주차가 없는 주변 주차장 조회도 실제 GPS를 사용한다. GPS를 받지 못하면 현재 위치 점을 숨기고, 예시 좌표로 주변 주차장을 조회하지 않는다.

## 4. 남은 연동 범위

- 지도 배경은 기존 OpenStreetMap을 유지한다. 카카오맵 패키지 설치와 배경 지도 교체는 별개다.
- 장소 검색·일부 화면의 지도 일러스트는 기존 데모이며, 실제 기기 연동으로 자동 교체되지 않는다.
- OS 위험 알림은 아직 연결하지 않았다. 주차 결과 알림은 기존 앱 내부 배너를 따른다.
- Android 실제 기기 기능은 API 서버 설정 여부와 별개로 사용한다. 웹은 기존 데모 GPS·기기 목록을 유지한다. Android에서 모의 GPS·연결 버튼은 노출하지 않는다.
- 서버 요청의 `lastKnownLocation` 별도 전송은 기존대로 null이다. 해제 순간 보관한 측위는 검증 후 `originalLocation`에 해당하는 GPS로 사용한다.

## 5. 개발 빌드와 시연

프로젝트 루트 `FE`에서 실행한다.

```bash
npm install
npm run prebuild:android
npm run android:device
```

1. Galaxy Z Flip3에서 휴대폰 블루투스 설정으로 이어폰·스피커를 페어링하고 연결한다.
2. 앱 권한 설정에서 정확한 위치·근처 기기를 허용한다. 백그라운드 위치 확보를 확인할 때는 위치 권한을 항상 허용으로 설정한다.
3. 내 차 등록 화면에서 그 기기를 선택한다. 홈의 실제 연결 상태가 연결됨인지 확인한다.
4. 기기의 전원을 끄거나 휴대폰 설정에서 연결을 해제한다. 홈에 주차 위치 확인이 나타나는지 확인한다.
5. 위치 확인에 들어가 실제 GPS 주소·정확도를 확인한다. 용인시 외부에서는 기존 정책대로 지원 지역 밖 안내가 나와야 한다.
6. 횡단보도 질문에 응답하고 기존 분석·기록 흐름을 확인한다.
7. 완료 전에 기기를 다시 연결했을 때 진행 취소를 확인한다. 다른 기기의 연결 해제가 새 주차를 만들지 않는지 확인한다.
8. 앱을 다른 화면 뒤로 보내거나 화면을 끄고 연결을 해제한 뒤 복귀해 이벤트가 반영되는지 확인한다.

블루투스가 없는 에뮬레이터는 실제 오디오 연결·해제를 검증할 수 없다. 에뮬레이터 GPS는 Extended controls의 Location에서 용인시 좌표를 지정해 확인할 수 있다.

## 6. 검사

```bash
npm run check
npm run test:device
npm run test:api
```

Android 모듈 테스트는 `FE/android`에서 실행한다.

```bash
./gradlew :vehicle-bluetooth:testDebugUnitTest
```

- 서비스·저장 복원 검사: 실제 기기 목록 전달, 권한·GPS 실패, 용인시 판별, 저장 측위 선택, 취소·지연 응답, 기존 계정 보존 등 19개.
- Android 상태 검사: 등록과 주차 구분, 다른 기기 무시, 중복 수신, 재연결·이벤트 확인 경쟁, 재연결 후 재해제, 계정 변경·로그아웃, JS 정지 중 보관·ACL 수신, 측위 유효성 등 10개.
- 자동 검사와 APK 빌드는 물리 기기의 실제 연결·해제 및 제조사별 백그라운드 동작 확인을 대체하지 않는다.
