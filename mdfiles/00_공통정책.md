# 세울까말까 — 공통 정책

기준일: 2026-11-07

이 문서는 전체 화면과 기능에 적용되는 제품 정책이다. 세부 구현 방법과 검증 조합은 [개발과 검증 계획](06_개발과_검증계획.md)의 구현 기본안으로 구분한다.

## 1. 서비스 범위

| 항목           | 기준                                                       |
| -------------- | ---------------------------------------------------------- |
| 서비스 표시명  | **세울까말까**                                             |
| 대상 사용자    | 용인시에서 차량을 운행·주차하는 운전자                     |
| 지원 지역      | 용인시 내 주차 위치                                        |
| 플랫폼·기술    | Android / React Native / TypeScript / Expo 전용 개발 빌드  |
| 지원 화면      | 완전히 펼친 세로 화면                                      |
| 확인 환경      | Galaxy Z Flip3(Android 15) 실기기와 Android 에뮬레이터     |
| 기본 탐색      | 홈 / 지도 / 주변 주차장 / 기록 / 마이페이지                |
| 현재 구현 범위 | 서버 API·Android 로그인·블루투스·GPS·OS 권한 연결, 웹 데모 |
| 후속 작업      | 실기기 검증, 지도·검색 SDK·OS 알림 등 잔여 연동            |

Android 15는 실기기 검증 환경이다. 현재 SDK의 빌드 하한은 min SDK 24다. 제품의 지원·검증 범위는 별도로 관리하며 [협업과 초기 세팅](08_협업과_초기세팅.md)을 따른다. 반접힘 전용 배치·커버 화면·가로 모드 전용 최적화는 지원 범위에 포함하지 않는다.

서비스명은 로그인·스플래시·앱 안내에 동일하게 적용한다. 로고는 서비스명 글자 중심의 임시안, 앱 아이콘은 교체 가능한 임시 자산을 사용한다.

## 2. 데모와 실제 연동의 경계

- API 서버 주소가 있으면 서버 API를 사용하고, 비어 있으면 모의 데이터·응답을 사용한다.
- Android는 실제 카카오 로그인·페어링 기기 조회·등록 기기의 연결 이벤트·GPS·OS 권한을 사용한다. 앱은 블루투스 페어링·연결을 직접 수행하지 않는다.
- 웹 기기 기능, 장소 검색과 일부 지도 일러스트는 데모다. 지도 탭 배경은 OpenStreetMap이며 카카오맵 교체와 구분한다. 세부 범위는 [실기기 블루투스와 GPS](11_실기기_블루투스와_GPS.md)를 따른다.
- 버튼·탐색·입력·타이머·모달·필터·상태 전환과 기기 데이터 저장은 실제로 동작하는 프론트 기능이다.
- 모의 조회·제출·지연·실패 주입·시연 제어는 화면과 분리한다. 실제 연동 경로에서는 제거·교체한다.
- 구현·자동 검사·실서버 확인·실기기 확인을 구분하고, 확인하지 않은 항목을 검증 완료로 표시하지 않는다.
- 예시 위험 수치·신고 건수·차트·주차장 거리·요금·운영 상태는 시연 데이터로 구분한다. 미제공 값을 실데이터처럼 채우지 않는다.
- 실제 기기 기능과 외부 SDK는 백엔드 API와 별도 연결·검증 대상으로 관리한다.

## 3. 앱 진입 조건

앱 실행 시 저장 상태를 읽고 로그인 → 권한 안내·온보딩 → 차량 등록의 완료 여부에 따라 진입 화면을 정한다.

- 홈과 하단 탭은 로그인 및 차량 1개 등록 완료 후 이용한다.
- 최초 차량 등록의 건너뛰기·미등록 둘러보기는 제공하지 않는다.
- 기기 미선택·목록 없음·등록 실패 상태는 안내·재시도를 제공하고 등록 화면에 머문다.
- 보관된 등록 차량은 재실행·재로그인 시 복원한다. 현재 차량 연결 여부는 등록 여부와 별개다.
- 뒤로 가기·딥링크·상태 복원에도 같은 진입 조건을 적용한다.
- 새 차량 등록 성공 시 기존 차량을 교체한다. 취소·실패 시 기존 등록과 이전 주차 기록을 유지한다.

## 4. 지원 지역과 위치

- 확보한 GPS 위치가 용인시 안일 때 주차 확인·타이머·분석을 진행한다.
- 사용자가 수정하거나 직접 지정한 위치에도 동일한 지역 조건을 적용한다.
- 용인시 밖에서는 지원 지역 안내를 제공하며 타이머·분석·새 주차 기록을 생성하지 않는다. 기존 로그인·저장 기록 조회는 유지한다.
- 좌표가 있으면 먼저 표시하고 사용자 핀 보정을 허용한다. 정확도 임계값으로 자동 확정을 차단하지 않는다.
- 위치를 확보하지 못한 경우에는 자동 확정을 끄고 직접 위치 지정·수동 확인으로 진행한다.
- 이번 단계의 위치·지원 지역 판별은 데모다. 실제 행정구역 판별 방법은 추후 연결한다.

## 5. 분석 결과와 기록

| 결과 상태        | 의미                                        | 기록 처리                       |
| ---------------- | ------------------------------------------- | ------------------------------- |
| 1단계            | 금지 구역 등 위험 근거를 보여주는 결과 유형 | 위치·주차 시각·상태·리포트 보관 |
| 2단계            | 신고 집중 등 위험 근거를 보여주는 결과 유형 | 위치·주차 시각·상태·리포트 보관 |
| 확인된 위험 없음 | 분석을 완료했으나 위험 요소를 찾지 못함     | 위험 표시가 없어도 보관         |
| 정보 부족        | 판단에 필요한 데이터가 부족함               | 위치·주차 시각·해당 상태 보관   |
| 분석 실패        | 분석 처리 중 오류 발생                      | 위치·주차 시각·해당 상태 보관   |

1·2단계는 현재 화면의 결과 분류다. 실제 등급 산정 기준·AI 모델·법적 판정 규칙은 미확정이며 데모로 재현한다.

- 저장 대상은 용인시 내 위치 확인·횡단보도 응답을 마치고 결과 상태가 정해진 주차다.
- 연결 해제만 발생한 미확인 내역은 진행 상태로 관리한다.
- 용인시 외 위치와 완료 전 재연결로 취소된 건은 새 기록을 남기지 않는다.
- 취소를 위험 미탐지·정보 부족·분석 실패로 바꾸어 저장하지 않는다.
- `확인된 위험 없음`은 안전·합법 주차의 보장이 아니며, 정보 부족·실패의 대체 문구로 쓰지 않는다.
- 같은 주차의 재시도는 동일 기록을 갱신하고 원래 위치·주차 시각을 유지한다. 중복 기록을 생성하지 않는다.
- 기록은 저장 당시의 결과를 보여준다. 상세 진입만으로 재분석하지 않는다.
- 사용자 횡단보도 응답은 자기보고 정보다. 정확한 거리 측정·위법 확정 결과와 구분한다.
- 실제 근거가 없는 단속 확률·법정 거리·과태료를 확정 정보로 표시하지 않는다.

## 6. 기기 저장과 계정 동작

| 동작          | 로그인 상태                                          | 데이터·진행 상태                                                                            |
| ------------- | ---------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| 앱 재실행     | 저장 상태 유지                                       | 등록 차량·완료 기록·설문 설정/응답/건너뛰기·데모 권한·안내 완료 상태·진행 중 위치 확인 복원 |
| 로그아웃      | 해제 후 로그인으로 이동. 재실행 후에도 로그아웃 유지 | 차량·기록·설문·설정 보관. 진행 화면은 로그인 후에만 복원                                    |
| 재로그인      | 데모 로그인 상태 활성화                              | 보관된 차량·기록·설정과 유효한 진행 상태 복원                                               |
| 차량 변경     | 유지                                                 | 새 등록 성공 시 차량 교체. 이전 기록 유지                                                   |
| 데모 초기화   | 첫 실행 로그인 상태                                  | 앱 소유 데모 데이터·예약 작업·진행 상태 정리. 설문 설정 기본 ON                             |
| 데모 회원탈퇴 | 첫 실행 로그인 상태                                  | 확인 후 앱 소유 데모 데이터 정리. 실제 계정 삭제는 추후 연동                                |

로그아웃 후 뒤로 가기로 인증된 화면에 재진입하지 않는다. 저장 상태 읽기에 실패하면 오류·재시도를 제공하고 보관 데이터를 자동 삭제하지 않는다. 취소·초기화·탈퇴 후 늦게 도착한 응답이나 저장 작업이 삭제된 상태를 복원하지 않도록 한다.

## 7. 알림과 앱 내부 안내

푸시·휴대폰 시스템 알림·별도 알림 발송 데모·알림 권한 요청·1단계/2단계/야간 알림 설정은 제공하지 않는다.

횡단보도 질문, 사후 설문, 결과·리포트, 로딩·오류·상태 안내는 앱 내부 UI로 제공한다. 백그라운드 만료나 이벤트를 이유로 앱을 강제로 앞으로 띄우지 않는다.

## 8. 화면과 디자인 공통 규칙

- [Figma 대상 섹션](https://www.figma.com/design/4LbuilpmFO0ycBcXZYc4qN/?node-id=197-3630)의 시각 스타일을 따른다. 기능·문구가 다르면 현재 기획 명세를 적용한다.
- 390×844 원본을 고정 기기 규격으로 쓰거나 전체 화면을 비율 축소하지 않는다.
- 가용 폭·높이·글자 배율에 맞춰 배치한다. 긴 주소·장소명·한글 문구의 줄바꿈을 허용한다.
- 카드·모달은 내용에 맞춰 높이를 조정하며, 짧은 화면에서는 스크롤로 모든 조작 요소에 접근할 수 있게 한다.
- 시스템 영역·키보드·하단 탭·고정 버튼의 겹침과 잘림을 방지한다. 글자 배율을 일괄 차단하거나 폰트를 축소해 배치 문제를 숨기지 않는다.
- 로딩·빈 상태·정보 부족·오류를 구분하고, 해당 상태에 맞는 재시도·검색·필터 변경 경로를 제공한다.
- 약관·개인정보 원문이 없으면 `내용 준비 중`으로 표시한다.
- 배터리 최적화 항목은 안내·설정 경로 데모로 제공하며 필수 진입 조건으로 차단하지 않는다.

배터리 안내, 모달의 세부 배치, 데모 탈퇴·초기화 확인 화면과 보조 버튼의 미리보기는 현재 구현 기본안이다. 사용자 확정 기능과 구체적인 구현 선택을 혼동하지 않는다.
