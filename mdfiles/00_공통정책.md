# 세울까말까 — 공통 정책

> 실제 데이터·권한·온보딩 기준: [온보딩과 실서비스 전환](12_온보딩과_실서비스_전환.md).
> 기준일: 2026-11-11

이 문서는 전체 화면과 기능에 적용되는 제품 정책이다. 세부 구현 방법과 검증 조합은 [개발과 검증 계획](06_개발과_검증계획.md)의 구현 기본안으로 구분한다.

## 1. 서비스 범위

| 항목           | 기준                                                      |
| -------------- | --------------------------------------------------------- |
| 서비스 표시명  | **세울까말까**                                            |
| 대상 사용자    | 용인시에서 차량을 운행·주차하는 운전자                    |
| 지원 지역      | 용인시 내 주차 위치                                       |
| 플랫폼·기술    | Android / React Native / TypeScript / Expo 전용 개발 빌드 |
| 지원 화면      | 완전히 펼친 세로 화면                                     |
| 확인 환경      | Galaxy Z Flip3(Android 15) 실기기와 Android 에뮬레이터    |
| 기본 탐색      | 홈 / 지도 / 주변 주차장 / 기록 / 마이페이지               |
| 현재 구현 범위 | 서버 API·Android 로그인·블루투스·GPS·OS 권한 연결         |
| 후속 작업      | 실기기 검증, 약관 원문·설문 서버 계약 등 미제공 항목      |

Android 15는 실기기 검증 환경이다. 현재 SDK의 빌드 하한은 min SDK 24다. 제품의 지원·검증 범위는 별도로 관리하며 [협업과 초기 세팅](08_협업과_초기세팅.md)을 따른다. 반접힘 전용 배치·커버 화면·가로 모드 전용 최적화는 지원 범위에 포함하지 않는다.

서비스명은 로그인·앱 안내에 동일하게 적용한다.

## 2. 실제 데이터 사용

서버 API와 기기 서비스만 사용한다. 서버 주소가 없으면 설정 오류를, 조회 실패·권한 거부 시에는 오류와 재시도를 표시한다. 가짜 로그인·기기·위치·위험 결과·주차장 목록이나 실패 주입 메뉴를 제공하지 않는다. 실제 지도·주소 검색·공유·길안내와 미제공 기능의 범위는 [실서비스 실행 기준](12_온보딩과_실서비스_전환.md)을 따른다.

구현·자동 검사·실서버 확인·실기기 확인은 구분한다. 미제공 통계·근거·요금 등을 임의로 채우지 않는다.

## 3. 앱 진입 조건

앱 실행 시 저장 상태를 읽고 로그인 → 남은 필수 약관 동의 → 권한 안내·온보딩 → 차량 등록의 완료 여부에 따라 진입 화면을 정한다.

- 홈과 하단 탭은 로그인 및 차량 1개 등록 완료 후 이용한다.
- 최초 차량 등록의 건너뛰기·미등록 둘러보기는 제공하지 않는다.
- 기기 미선택·목록 없음·등록 실패 상태는 안내·재시도를 제공하고 등록 화면에 머문다.
- 보관된 등록 차량은 재실행·재로그인 시 복원한다. 현재 차량 연결 여부는 등록 여부와 별개다.
- 뒤로 가기·딥링크·상태 복원에도 같은 진입 조건을 적용한다.
- 새 차량 등록 성공 시 기존 차량을 교체한다. 취소·실패 시 기존 등록과 이전 주차 기록을 유지한다.

## 4. 지원 지역과 위치

- 확보한 GPS 위치가 용인시 안일 때 주차 확인·타이머·분석을 진행한다.
- 사용자가 수정하거나 직접 지정한 위치에도 동일한 지역 조건을 적용한다.
- 용인시 밖에서는 지원 지역 안내를 제공하며 타이머·분석·새 주차 기록을 생성하지 않는다. 기존 로그인·저장 기록 조회는 유지한다.
- 좌표가 있으면 중앙 고정 핀 아래에 먼저 표시하고 사용자가 지도를 움직여 위치를 보정할 수 있게 한다. 자동 확정은 GPS 정확도 15m 이내에서만 사용한다. 15~50m는 직접 확인하고, 50m 초과·측위 실패 시 직접 위치를 지정한다.
- 위치를 확보하지 못한 경우에는 자동 확정을 끄고 직접 위치 지정·수동 확인으로 진행한다.
- 역지오코딩의 실제 행정구역으로 용인시 여부를 판별한다. 주소 조회 실패를 지원 지역으로 단정하지 않는다.

## 5. 분석 결과와 기록

| 결과 상태      | 의미                                        | 기록 처리                       |
| -------------- | ------------------------------------------- | ------------------------------- |
| 1단계          | 금지 구역 등 위험 근거를 보여주는 결과 유형 | 위치·주차 시각·상태·리포트 보관 |
| 2단계          | 신고 집중 등 위험 근거를 보여주는 결과 유형 | 위치·주차 시각·상태·리포트 보관 |
| 주의 구역 아님 | 분석을 완료했으나 위험 요소를 찾지 못함     | 위험 표시가 없어도 보관         |
| 정보 부족      | 판단에 필요한 데이터가 부족함               | 위치·주차 시각·해당 상태 보관   |
| 분석 실패      | 분석 처리 중 오류 발생                      | 위치·주차 시각·해당 상태 보관   |

단계·근거·통계는 서버 응답을 기준으로 표시한다. 1단계·2단계·3단계는 서버와 문서에서만 쓰는 이름이고, 화면에는 숫자 단계를 쓰지 않는다. 1단계는 `주정차 금지 구역`(배지는 `소화전 주변 금지 구역`처럼 시설 이름을 붙이고 필터는 `금지 구역`), 2단계는 `신고 다발 구역`(필터는 `신고 다발`), 3단계는 `주의 구역 아님`으로 표시한다. 이전에 저장한 기록의 배지도 읽을 때 같은 문구로 바꾼다. 분석 성공이어도 단계가 누락·미지원 값이면 판단 불가로 처리하고 명확한 3단계만 주의 구역 아님으로 표시한다. 횡단보도 `예` 응답은 앱에서 직접 응답을 근거로 1단계에 반영하고 원래 서버 결과와 구분한다. 시민 신고 위험 모델은 [백엔드 AI 자료](10_AI_모델과_학습데이터.md)를 따른다.

- 저장 대상은 용인시 내 위치 확인·횡단보도 응답을 마치고 결과 상태가 정해진 주차다.
- 연결 해제만 발생한 미확인 내역은 진행 상태로 관리한다.
- 용인시 외 위치와 완료 전 재연결로 취소된 건은 새 기록을 남기지 않는다.
- 취소를 위험 미탐지·정보 부족·분석 실패로 바꾸어 저장하지 않는다.
- `주의 구역 아님`은 안전·합법 주차의 보장이 아니며, 정보 부족·실패의 대체 문구로 쓰지 않는다.
- 같은 주차의 재시도는 동일 기록을 갱신하고 원래 위치·주차 시각을 유지한다. 중복 기록을 생성하지 않는다.
- 기록은 저장 당시의 결과를 보여준다. 상세 진입만으로 재분석하지 않는다. 서버 목록은 최대 100건의 일부 응답이므로 목록에 없는 기기 기록을 삭제하지 않는다. 오래된 기록의 직접 응답·제출값도 유지하고 단계별 필터에 포함한다.
- 사용자 횡단보도 응답은 자기보고 정보다. `예`는 1단계 리포트, `아니요`는 서버 판정을 적용한다. 정확한 거리 측정·위법 확정 결과와 구분한다.
- 실제 근거가 없는 단속 확률·법정 거리·과태료를 확정 정보로 표시하지 않는다.

## 6. 기기 저장과 계정 동작

| 동작      | 로그인 상태                                          | 데이터·진행 상태                                                                            |
| --------- | ---------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| 앱 재실행 | 저장 상태 유지                                       | 등록 차량·완료 기록·설문 설정/응답/건너뛰기·기기 권한·안내 완료 상태·진행 중 위치 확인 복원 |
| 로그아웃  | 해제 후 로그인으로 이동. 재실행 후에도 로그아웃 유지 | 차량·기록·설문·설정 보관. 진행 화면은 로그인 후에만 복원                                    |
| 재로그인  | 카카오 SDK와 서버 인증                               | 보관된 차량·기록·설정과 유효한 진행 상태 복원                                               |
| 차량 변경 | 유지                                                 | 새 등록 성공 시 차량 교체. 이전 기록 유지                                                   |
| 회원탈퇴  | 첫 실행 로그인 상태                                  | 서버 계정 삭제 성공 후 앱 소유 데이터 정리                                                  |

로그아웃 후 뒤로 가기로 인증된 화면에 재진입하지 않는다. 저장 상태 읽기에 실패하면 오류·재시도를 제공하고 보관 데이터를 자동 삭제하지 않는다. 취소·초기화·탈퇴 후 늦게 도착한 응답이나 저장 작업이 삭제된 상태를 복원하지 않도록 한다.

## 7. 알림과 앱 내부 안내

시스템 알림은 주차 감지 알림 하나만 제공한다. 앱이 화면에 없을 때 등록 차량의 블루투스 연결이 끊기면 기기에서 `주차를 감지했어요` / `위치를 확인해 주세요` 알림을 띄우고, 누르면 홈을 거쳐 위치 확인 화면으로 들어간다. 알림 권한은 선택이며 거절해도 주차 확인은 그대로 쓸 수 있다. 재연결되거나 앱이 해당 이벤트를 처리하면 알림을 지운다. 서버 푸시·위험 결과 알림·자동 위험 배너·알림 설정은 제공하지 않는다. 서버의 `notify` 응답은 사용하지 않으며 알림 설정과 delivery API를 호출하지 않는다. 위험 정보는 주차 결과와 기록 리포트에서 확인한다.

횡단보도 질문, 사후 설문, 결과·리포트, 로딩·오류·상태 안내는 앱 내부 UI로 제공한다. 백그라운드 만료나 이벤트를 이유로 앱을 강제로 앞으로 띄우지 않는다.

## 8. 화면과 디자인 공통 규칙

- [Figma 대상 섹션](https://www.figma.com/design/4LbuilpmFO0ycBcXZYc4qN/?node-id=197-3630)의 시각 스타일을 따른다. 기능·문구가 다르면 현재 기획 명세를 적용한다.
- 390×844 원본을 고정 기기 규격으로 쓰거나 전체 화면을 비율 축소하지 않는다.
- 가용 폭·높이·글자 배율에 맞춰 배치한다. 긴 주소·장소명·한글 문구의 줄바꿈을 허용한다.
- 앱 텍스트는 Pretendard Regular, Bold, Black을 사용한다. 자간은 글자 크기의 -2%이며 제목 줄간격은 150%, 본문·보조 문구는 160%로 통일한다. 사용자 지정 글자 크기에도 같은 비율을 계산한다.
- 가운데 점·긴 대시로 메타정보를 이어 붙이지 않는다. 위치·시간·요금·기기 상태는 의미 있는 아이콘과 텍스트로 묶고 좁은 폭에서는 항목 단위로 줄바꿈한다. 안내 문장은 자연스러운 접속어나 쉼표로 연결한다.
- 카드·모달은 내용에 맞춰 높이를 조정하며, 짧은 화면에서는 스크롤로 모든 조작 요소에 접근할 수 있게 한다.
- 시스템 영역·키보드·하단 탭·고정 버튼의 겹침과 잘림을 방지한다. 글자 배율을 일괄 차단하거나 폰트를 축소해 배치 문제를 숨기지 않는다.
- 로딩·빈 상태·정보 부족·오류를 구분하고, 해당 상태에 맞는 재시도·검색·필터 변경 경로를 제공한다.
- 약관·개인정보 원문이 없으면 `내용 준비 중`으로 표시한다.
- 배터리 최적화 항목은 실제 Android 설정 진입으로 제공하며 필수 진입 조건으로 차단하지 않는다.

배터리 예외는 선택이며 설정을 강제로 변경하지 않는다.
