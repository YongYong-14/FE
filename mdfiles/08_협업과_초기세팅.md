# 세울까말까 — 협업과 초기 세팅

기준일: 2026-11-07 · 작업 루트: `FE/`

## 1. 브랜치 정책

| 브랜치    | 담당·역할             | PR 대상        |
| --------- | --------------------- | -------------- |
| `main`    | 검증된 통합 결과      | `dev`에서 반영 |
| `dev`     | 두 개발자의 작업 통합 | `main`         |
| `onjunku` | 온준규 개인 작업      | `dev`          |
| `ummpa`   | 김서은 개인 작업      | `dev`          |

일반 개발 흐름은 **개인 브랜치 → dev → main**이다. 초기 설정은 2026-11-07 사용자 요청에 따라 `main`으로 직접 공유한다. 로컬 개발은 `onjunku`에서 진행하며 `dev`·`ummpa`도 로컬에 준비했다. 초기 설정은 원격 `main`에 반영했으며 원격 `dev`·개인 브랜치 생성과 PR·통합 병합은 별도 후속 작업이다. 최초 원격 확인 시에는 `main`만 존재했다.

### 개인 브랜치 운영 기본안

- 두 개인 브랜치는 계속 사용하며 PR 병합 후 삭제하지 않는다.
- 공통 조상 관계를 유지하도록 일반 merge commit 방식의 병합을 기본안으로 둔다. 개인 브랜치의 이력을 다시 쓰거나 강제 푸시하지 않는다.
- 새 작업 전 원격 `dev`를 가져와 자신의 개인 브랜치에 병합한다. 병합 후 의존성이 바뀌었으면 `npm ci`를 실행한다.
- 충돌이 생기면 자신의 브랜치에서 해결하고 공통 검사를 통과한 뒤 PR을 갱신한다.
- 다른 개발자의 개인 브랜치를 직접 수정하지 않는다.

```bash
# 본인 브랜치에서 최신 통합 결과 반영
git fetch origin
git switch onjunku
git merge origin/dev
npm ci
npm run check
```

김서은의 작업 브랜치 이름은 같은 절차에서 `ummpa`로 사용한다. 위 명령은 원격 `dev`가 생성되고 초기 설정이 반영된 이후에 실행한다.

새로 클론한 환경에서 원격 개인 브랜치가 있으면 `git switch --track origin/ummpa`로 연결한다. 개인 브랜치가 아직 원격에 없다면 초기 설정이 반영된 `origin/dev`에서 `git switch -c ummpa origin/dev`로 생성한다.

### GitHub에 적용할 보호 설정

아래는 권장 설정이며 현재 원격 저장소에 적용하지 않았다.

- `main`·`dev` 직접 푸시 대신 PR 사용.
- `Frontend checks` 성공을 병합 조건으로 설정.
- 다른 개발자 1명의 리뷰 승인을 기본안으로 사용.
- 장기 개인 브랜치가 자동 삭제되지 않도록 병합 후 브랜치 삭제 설정 확인.

CI는 개인 브랜치 → `dev`, `dev` → `main` 외의 PR 경로를 실패 처리한다. 실제 보호 규칙을 켜기 전에는 CI 실패만으로 GitHub 병합이 강제 차단되지는 않는다.

Git 작성자 정보는 개발자별로 이 저장소의 로컬 설정에 둔다. 현재 작업 환경은 GitHub 계정 `onjunku`와 해당 계정의 no-reply 이메일을 사용하며 전역 Git 설정은 변경하지 않았다.

min SDK 24는 현재 템플릿의 빌드 하한이다. Android 7부터 모든 화면·기기 동작을 검증했다는 뜻이 아니다. 실기기 목표 OS는 Android 15이며 최소 지원 정책과 검증 범위는 구분한다.

의존성의 직접 버전과 `package-lock.json`을 함께 관리하고 협업 환경에서는 `npm ci`로 설치한다. 패키지 추가·업데이트 시 Expo 호환성을 확인하고 lockfile을 같은 PR에 포함한다.

현재 `.env`나 실제 서비스 키는 필요하지 않다. `.env.example`은 이 상태를 안내하며 `.env`는 Git에서 제외한다. 실제 연결 정보는 [API 연동 계획](03_API_연동_대기.md)의 범위에서 추후 추가한다.

## 4. 공통 작업 규칙

- 현재 화면·기능은 모두 `onjunku`에서 구현했다. 이후 수정·연동 작업의 분담은 [역할 분담](09_프론트_역할분담.md)을 기준으로 다시 정한다.
- 공통 타입·테마·provider·서비스 진입점·패키지·앱 설정 변경은 PR 설명에 영향 범위를 적는다.
- 화면에서 `services/demo`를 직접 참조하지 않고 `services` 공개 진입점을 사용한다.
- 기능 전용 코드는 해당 기능에 두고, 공통 코드의 위치는 [폴더 구조](07_폴더구조.md)를 따른다.
- 앱의 로그인·차량 등록 조건을 확인 목적으로 우회하지 않는다.
- 실제 위치·블루투스·알림 권한은 요청하지 않는다. 이번 단계에 필요한 OS 권한을 추가하지 않는다.
- 자동 수정 가능한 포맷·린트는 도구에 맡긴다. 개발자마다 다른 포맷 설정을 추가하지 않는다.

현재 `npm audit`은 moderate 12건(high·critical 0건)을 보고한다. `glob`·`minimatch` 및 이를 사용하는 Expo CLI·fingerprint·린트 의존성 경로다. SDK 호환 버전을 유지하며 강제 다운그레이드나 검증되지 않은 전역 override는 적용하지 않았다. 공식 호환 업데이트 시 다시 확인한다. 실제 앱 노출 가능성과 설치 트리의 경고 수를 동일시하지 않는다.

API 35의 기본 진입 확인: 로그인 전 홈 접근 차단, 안내 후 차량 등록, 미선택 등록 차단, 5탭 표시, 로그아웃·재로그인 시 차량 복원을 확인했다. 완전 종료 후 로그인·차량·설문 OFF 설정 복원과 로그아웃 상태 유지도 확인했다. 정상 콜드 시작 후의 해당 흐름에서 ReactNativeJS·AndroidRuntime 오류 로그가 없었다.

개발 클라이언트 URL을 반복해서 여는 테스트에서 내비게이션 컨테이너 경고가 관찰됐다. 앱을 완전히 종료한 뒤 정상 재시작·로그아웃·재로그인한 흐름에서는 재현되지 않았다. 실제 제품의 전체 딥링크·뒤로 가기 검증 완료를 뜻하지 않는다.

PR 대상 검사도 허용 3건·차단 3건의 총 6개 조합을 로컬에서 확인했다. `npm ci`로 lockfile 재설치를 확인했고 생성된 네이티브 폴더·환경 파일·node_modules·OS 파일의 Git 제외 여부를 점검했다.

검증 기기는 로컬 AVD `Seulkka_API_35`(Android 15, arm64, Pixel 5 프로필)다. 검증용 개발 서버와 headless 에뮬레이터는 확인 후 종료하며 Android Studio Device Manager에서 같은 AVD를 다시 실행할 수 있다.

## 6. 남은 협업 결정

### 에뮬레이터 선택과 개발 빌드 설치

- API 35는 Flip3의 Android 15와 같은 OS 버전에서 검증하기 위한 기준이며 API 37 사용을 제한하지 않는다.
- 개발 빌드는 기기별 설치다. 다른 AVD가 열리면 해당 AVD에도 개발 빌드를 먼저 설치해야 `npm start`에서 앱을 열 수 있다.
- 2026-11-07 `Medium_Phone_API_37.0`에 기존 debug APK 설치에 성공했다. 실행 명령 전달 후 확인 과정에서 ADB 연결이 끊겼으므로 해당 환경의 화면·전체 동작 검증은 미완료다.
- 새 기기를 선택해 빌드·설치하려면 `npm run android:device`를 사용한다. 기존 개발 서버가 실행 중이면 해당 서버를 재사용할 수 있다.
- 2026-11-09 Galaxy Z Flip3(`SM-F711N`, Android 15)에 개발 빌드를 설치하고 USB로 기존 Metro 서버에 연결해 로그인 화면 진입을 확인했다. `No development build`의 원인은 해당 실기기에 개발 빌드가 설치되지 않은 것이었다. 기기 최초 실행은 `npm run android:device`, 설치 이후에는 `npm start`를 사용한다.

### 협업 후속 항목

- 팀원1·팀원2의 기능 배분안은 작성했으며 실제 개발자와 번호의 연결은 미정이다.
- 권장 리뷰·보호 설정의 실제 GitHub 적용과 원격 `dev`·개인 브랜치 준비.
- 실기기의 전체 화면·큰 글자 배율·전체 시나리오 검증 및 Figma 정밀 대조.

백엔드 키·API 계약·지도 공급자는 현재 결정·요청 대상이 아니다.
