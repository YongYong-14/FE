# 세울까말까 — 폴더 구조

기준일: 2026-11-07 · 프로젝트 루트: `FE/`

React Native·TypeScript·Expo Router 기반의 기능별 구조다. 화면 경로, 기능 코드, 공통 UI, 데이터 연결, 기기 저장을 구분한다.

폴더 구조 생성 후 Expo 프로젝트·협업 초기 설정을 진행했다. 현재 파일과 검증 범위는 [협업과 초기 세팅](08_협업과_초기세팅.md)에 기록한다. 상세 제품 화면·주차 기능·실제 외부 연동은 별도 구현 단계다.

## 1. 전체 구조

아래 구조를 기준으로 파일을 배치한다. 생성된 소스 파일과 `.gitkeep`은 표에서 생략한다.

## 2. 루트와 자산

| 경로             | 역할                                                                    |
| ---------------- | ----------------------------------------------------------------------- |
| `FE/`            | 프론트엔드 앱의 프로젝트 루트. 추후 Expo·패키지 설정을 이 위치에서 관리 |
| `mdfiles/`       | 기획·공통 정책·화면·주차 진행·연동 대기·시연·개발 계획                  |
| `assets/`        | 앱에서 사용하는 실제 파일 자산                                          |
| `assets/fonts/`  | Noto Sans KR 등 사용 서체 파일                                          |
| `assets/images/` | 로고·이미지·일러스트                                                    |
| `assets/icons/`  | 앱 아이콘과 파일 형태의 아이콘 자산                                     |

자산 폴더 생성은 실제 폰트·이미지 확보나 제작을 의미하지 않는다. 코드로 작성하는 공통 아이콘 컴포넌트는 `src/shared/components/`에 둔다.

## 3. 화면 경로 — src/app

| 경로                       | 역할                                                |
| -------------------------- | --------------------------------------------------- |
| `src/`                     | 앱 소스 코드의 최상위 디렉터리                      |
| `src/app/`                 | Expo Router의 화면 경로·레이아웃·화면 이동 구성     |
| `src/app/(onboarding)/`    | 로그인, 권한 안내·온보딩, 최초 차량 등록의 경로     |
| `src/app/(main)/`          | 로그인과 차량 등록 완료 후 진입하는 영역            |
| `src/app/(main)/(tabs)/`   | 홈·지도·주변 주차장·기록·마이페이지의 하단 5탭 경로 |
| `src/app/(main)/parking/`  | 주차 위치 확인·분석 결과 화면의 경로                |
| `src/app/(main)/records/`  | 기록 ID별 상세 화면의 경로                          |
| `src/app/(main)/settings/` | 차량 변경·약관·데모 설정 등 보조 화면의 경로        |

라우트 파일은 해당 기능의 화면 컴포넌트를 연결하고 경로 파라미터를 전달한다. 타이머·분석·저장 로직을 라우트 파일에 직접 모으지 않는다.

`(onboarding)`, `(main)`, `(tabs)`는 URL 경로에 추가되지 않는 라우트 그룹이다. 그룹 이름만으로 접근이 제한되는 것은 아니며, 로그인·차량 등록 검사는 레이아웃과 상태 처리로 구현한다. 일반 컴포넌트·훅·자료형은 `src/app/` 밖에 둔다.

### 주요 라우트 파일

| 경로                                     | 역할                                        |
| ---------------------------------------- | ------------------------------------------- |
| `src/app/_layout.tsx`                    | 루트 레이아웃, 폰트·테마·공통 상태 연결     |
| `src/app/index.tsx`                      | 저장 상태 확인 후 시작 경로로 이동          |
| `src/app/(onboarding)/_layout.tsx`       | 로그인·안내·등록 단계 구성                  |
| `src/app/(main)/_layout.tsx`             | 로그인·차량 등록 조건 확인과 공통 화면 스택 |
| `src/app/(main)/(tabs)/_layout.tsx`      | 하단 5탭 구성                               |
| `src/app/(main)/(tabs)/home.tsx`         | 홈                                          |
| `src/app/(main)/(tabs)/map.tsx`          | 지도                                        |
| `src/app/(main)/(tabs)/parking-lots.tsx` | 주변 주차장                                 |
| `src/app/(main)/(tabs)/history.tsx`      | 기록                                        |
| `src/app/(main)/(tabs)/mypage.tsx`       | 마이페이지                                  |

루트의 `index.tsx`는 초기 이동 전용으로 두고 홈은 `home.tsx`로 구분한다. 주요 라우트는 생성했다. 상세 기능이 없는 경로는 안내 화면이며 실제 기능 구현 완료로 표시하지 않는다.

## 4. 기능별 구현 — src/features

| 경로            | 담당 기능                                                      |
| --------------- | -------------------------------------------------------------- |
| `src/features/` | 기능별 화면·전용 컴포넌트·상태·처리 코드                       |
| `auth/`         | 데모 로그인 성공·실패, 인증 상태, 권한 안내·온보딩 화면        |
| `vehicle/`      | 차량 목록·선택·등록·변경, 차량 연결 상태                       |
| `home/`         | 홈 화면, 최근 주차 요약, 진행 중 확인 진입                     |
| `parking/`      | 위치 확인, 타이머·게이지, 횡단보도 모달, 분석·결과·재연결 취소 |
| `map/`          | 지도 탭, 장소 검색·결과 선택, 위험 구역·신고 건수 표시 제어    |
| `parking-lots/` | 주변 주차장 목록·반경·필터·핀 선택·보조 동작 미리보기          |
| `history/`      | 기록 목록·6개 필터·당시 상세·동일 기록 재시도·목록 위치 복귀   |
| `survey/`       | 사후 설문 대상·응답·건너뛰기·중복 노출 방지                    |
| `settings/`     | 마이페이지, 설정·권한 안내, 로그아웃·탈퇴 화면                 |
| `demo/`         | 데모 설정 화면, 시나리오 선택·예약·초기화 조작                 |

표의 기능 경로는 모두 `src/features/` 아래다. 예를 들어 `settings/`는 `src/features/settings/`를 뜻한다.

### parking 내부 구조

| 경로                           | 역할                                                       |
| ------------------------------ | ---------------------------------------------------------- |
| `parking/screens/`             | 위치 확인·분석 결과 등 완성된 화면                         |
| `parking/components/`          | 해당 기능 전용 타이머·게이지·횡단보도 모달·결과 카드       |
| `parking/hooks/`               | 화면에서 주차 상태·이벤트·앱 수명주기를 사용하는 훅        |
| `parking/state/`               | 주차 단계·시간·좌표·응답·분석·취소·복원의 일관된 상태 처리 |
| `parking/utils/`               | 주차 기능 전용 계산·변환 등 독립 함수                      |
| `parking/types.ts` — 예정 파일 | 주차 단계·결과·이벤트 등 기능 전용 타입                    |

진행 중 주차 상태는 `parking/state/`가 소유하고 앱 상위의 provider에서 연결한다. 확인 화면을 나가거나 탭을 이동해도 같은 상태를 사용한다. 위치 타이머·횡단보도 모달·분석을 화면마다 별도로 생성하지 않는다.

다른 기능에도 필요한 시점에 `screens/`, `components/`, `hooks/`, `state/`, `utils/`, `types.ts`를 추가한다. 모든 기능에 같은 하위 폴더를 일괄 생성하지 않는다.

## 5. 공통 코드 — src/shared

| 경로          | 역할                                                          |
| ------------- | ------------------------------------------------------------- |
| `src/shared/` | 특정 기능에 종속되지 않고 여러 기능이 함께 사용하는 코드      |
| `components/` | 버튼·텍스트·카드·모달·화면 틀·공통 상태 안내                  |
| `map/`        | 여러 화면이 사용하는 지도 표시 컴포넌트와 공통 좌표·마커 규격 |
| `theme/`      | Figma 기준 색상·서체·간격·라운드 토큰                         |
| `hooks/`      | 여러 기능에서 사용하는 범용 훅                                |
| `utils/`      | 공통 날짜·시간·거리·문자열 변환                               |
| `types/`      | 여러 기능이 공유하는 기본 자료형                              |

표의 하위 경로는 모두 `src/shared/` 아래다.

공통 모달의 틀은 `shared/components/`, 횡단보도 질문 내용·응답 처리는 `features/parking/`에 둔다. 지도 표시·좌표 규격은 `shared/map/`, 지도 탭의 검색·건수 제어는 `features/map/`에서 담당한다.

한 기능에서만 사용하는 코드·타입은 해당 기능에 둔다. `shared`가 기능 코드를 가져오는 역방향 의존은 만들지 않는다.

## 6. 연결·저장·앱 초기화

| 경로                     | 역할                                                                             |
| ------------------------ | -------------------------------------------------------------------------------- |
| `src/services/`          | 기능 코드가 사용하는 데이터·기기 기능 연결 지점. 내부 호출 규격과 결과 변환 관리 |
| `src/services/demo/`     | 로그인·블루투스·GPS·분석·검색·주차장 등 모의 조회·응답·이벤트                    |
| `src/services/fixtures/` | 예시 장소·차량·주차장·리포트·차트 등 시연 데이터                                 |
| `src/storage/`           | AsyncStorage 연결, 앱 소유 키, 읽기·쓰기·복원·초기화 처리                        |
| `src/providers/`         | 앱 전체에서 유지할 상태 provider 조합, 저장 상태 초기 읽기·앱 수명주기 연결      |

`features/demo/`는 시연을 조작하는 UI이고 `services/demo/`는 모의 동작이다. `fixtures/`는 예시 값이며 실제 API 응답 계약으로 취급하지 않는다.

기능 화면은 모의 응답 구현을 직접 가져오기보다 `services/`의 공개 진입점을 사용한다. 연결 인터페이스와 진입 파일은 기능 구현 시 필요한 만큼 정의하며, 지금 실제 API 폴더·요청 타입·엔드포인트를 만들지 않는다.

데이터 저장 도구는 `storage/`, 어떤 상태를 언제 저장할지는 각 기능의 정책이 담당한다. `providers/`는 연결·초기화를 담당하며 기능별 상태 로직을 한 파일에 모두 모으지 않는다.

## 7. 파일 배치·참조 규칙

1. 라우트는 `app/`, 화면과 기능 처리는 `features/`에 둔다.
2. 기능 전용 UI·타입·훅은 해당 기능에 둔다. 여러 기능에서 실제로 함께 쓸 때 공통화를 검토한다.
3. 공통 UI와 도구는 `shared/`, 외부·데모 연결은 `services/`, 영속 저장 도구는 `storage/`로 구분한다.
4. `shared/`, `services/`, `storage/`가 라우트나 기능 화면을 가져오지 않도록 한다.
5. 기능 간 참조는 필요한 공개 진입점으로 제한한다. 다른 기능의 내부 상태 파일을 직접 참조하거나 순환 의존을 만들지 않는다.
6. 공통 상수는 `theme/` 또는 해당 기능에 둔다. 용도가 다른 상수·타입을 하나의 전역 파일에 계속 쌓지 않는다.
7. 폴더는 소문자·단어 사이 하이픈, 컴포넌트는 PascalCase, 훅은 `use...` 이름을 기본으로 한다. Expo Router의 특수 파일명은 해당 규칙을 따른다.
8. 검증 파일이 필요한 경우 관련 기능·모듈 가까이에 둔다. 현재는 앱 테스트 파일을 생성하지 않는다.

## 8. 생성 상태와 후속 작업

- 디렉터리 구조와 초기 소스·설정 파일을 생성했다. 실제 파일이 없는 말단 폴더에는 `.gitkeep`을 유지한다.
- `.gitkeep`은 Git에서 빈 폴더를 보존하기 위한 자리표시 파일이다. 실제 파일이 들어오면 해당 폴더의 `.gitkeep`을 제거할 수 있다.
- 초기 설정의 Git 반영과 브랜치 운영은 [협업 가이드](08_협업과_초기세팅.md)를 따른다.
- `app.config.ts`, `package.json`, `tsconfig.json`, 주요 라우트·초기 기능 코드가 생성됐다. 폰트는 패키지에서 필요한 굵기를 로드하며 최종 브랜드 자산은 대기 중이다.
- 기존 기획·공통 정책·API 대기·팀 공유 범위는 유지한다.
- 앱 초기화·패키지·버전·실행 환경은 [개발과 검증 계획](06_개발과_검증계획.md)을 따른다.

기술 기준: [Expo Router 기본 개념](https://docs.expo.dev/router/basics/core-concepts/), [라우트 그룹·파일 표기](https://docs.expo.dev/router/basics/notation/).
