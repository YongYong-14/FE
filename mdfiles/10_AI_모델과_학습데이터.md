# 세울까말까 — AI 모델과 학습 데이터

자료 수령일: 2026-11-10 · 출처: 백엔드 전달 모델 개발 설명 및 첨부 원본 자료

이 문서는 백엔드가 전달한 AI 모델의 학습 방식, 평가 결과, 데이터 범위와 발표·화면 표현 기준을 정리한다. AI가 예측하는 대상은 **시민 신고 건수와 신고 집중 순위**다. 실제 단속 여부·단속 확률·주차의 합법 여부를 예측하는 모델로 설명하지 않는다.

학습·평가 수치는 백엔드 공유값이다. 이번 정리는 모델 재학습이나 원본 데이터의 전처리 재현 검증을 수행한 결과가 아니다. 공유 내용의 산술 불일치와 미제공 정보는 마지막 확인 사항에 구분한다. 이 자료를 기록하는 것만으로 기존 화면·기능·API 구현을 변경하지 않는다.

## 1. 전달 자료와 출처

| ------------------------------------------- | ---------------------------------------------------------------- |
| 백엔드 모델 개발 설명                       | 학습·평가 방식, 전처리 단계별 건수, 성능 수치와 발표 표현의 출처 |
| `경기도 용인시_주정차단속현황_20251115.csv` | 백엔드가 함께 전달한 주정차 단속 원본 자료                       |

첨부 파일의 로컬 위치는 `/Users/on/Downloads/`이며, 두 파일의 존재를 확인했다. 원본 파일은 수정하거나 저장소에 복사하지 않았다. CSV·Excel의 개별 행·집계값과 학습 데이터의 일치 여부는 이번 문서 작성에서 별도로 검증하지 않았다. 원본 파일명에 포함된 날짜를 학습·관측 기간으로 사용하지 않는다.

원본 파일의 전체 건수, 시민 신고 건수, 좌표 변환 성공 건수와 최종 모델 사용 건수는 서로 다른 전처리 단계의 수치다. 특정 Excel 파일의 건수를 모델의 최종 학습 데이터 수로 대체하지 않는다.

## 2. 1단계와 2단계의 역할

| 구분  | 처리 방식                       | 백엔드 전달 기준                                                 |
| ----- | ------------------------------- | ---------------------------------------------------------------- |
| 1단계 | 시설과의 거리 규칙              | 소화전 5m, 버스정류소 10m. AI 모델을 사용하지 않음               |
| 2단계 | 시민 신고 건수 예측과 상대 순위 | 같은 요일·시간대에서 예측값이 상위 10%인 칸을 주의 대상으로 표시 |

위 거리 값은 백엔드가 공유한 서비스 판정 규칙을 기록한 것이다. 모델 성능 평가 수치는 2단계의 시민 신고 예측에 관한 값이며, 1단계 규칙의 정확도나 실제 단속 여부의 예측 성능을 뜻하지 않는다.

## 3. 학습 방식

1. 용인시 주정차 단속 자료에서 **안전신문고와 새올민원에 해당하는 시민 신고**를 추린다. 단속반의 단속 기록 전체를 학습 대상으로 사용하는 것은 아니다.
2. 지번 주소를 좌표로 변환한다. 좌표 변환 실패와 위치가 모호한 주소는 제외한다.
3. 좌표를 용인시 전체를 덮는 **50m 격자 칸**에 배정한다.
4. **칸 × 요일 × 시간대**별 신고 건수를 집계한다. 요일은 7개, 시간대는 3시간 단위 8개로, 칸마다 56개 조합이 있다.
5. 해당 칸·요일·시간대의 **하루 평균 시민 신고 건수**를 예측하는 **LightGBM 포아송 회귀 모델**을 학습한다.
6. 예측값을 같은 요일·시간대 안에서 비교해 상대 순위로 변환한다.
7. 상위 10% 칸을 앱의 2단계 주의 대상으로 사용한다.

요일·시간대 조합별로 순위를 계산하므로, 서로 다른 요일이나 시간대의 예측값을 모두 섞어 상위 10%를 고르는 방식으로 설명하지 않는다.

## 5. 평가 지표

### 주 지표 위험 상위 N퍼센트 칸의 신고 포착률

요일·시간대마다 모델이 위험하다고 고른 상위 N% 칸에서 테스트 기간 실제 시민 신고의 몇 %가 발생했는지를 본다. 앱의 2단계 기준이 상위 10%이므로 **상위 10% 칸 포착률**을 주 지표로 사용한다.

포착률은 신고를 얼마나 많이 포함했는지의 지표다. 경고한 칸 중 실제 신고가 있었던 비율이나 개별 주차의 신고 확률을 뜻하지 않는다. `모델 정확도 94.8%`처럼 일반적인 정확도 지표로 바꾸어 표현하지 않는다.

### 보조 지표 건수 예측 개선율

Poisson deviance를 기준으로, 모든 칸에 평균 신고 건수를 예측하는 기준보다 건수 예측 오차가 얼마나 줄었는지를 평가한다. 공유된 개선율은 베이스라인 **9.8%**, LightGBM **58.7%**다. `LightGBM이 비교 베이스라인보다 오차를 58.7% 더 줄였다`는 의미로 사용하지 않는다.

### AUC와 F1을 주 지표로 쓰지 않은 이유

모델의 목표가 신고 유무 이진 분류가 아니라 건수 예측과 순위 선정이기 때문이다. 앱에서 상위 칸에 주의를 안내하는 사용 방식에 맞춰 신고 포착률로 평가했다는 것이 백엔드의 설명이다.

## 6. 베이스라인과 모델 성능

베이스라인의 정확한 설명은 **칸×요일×시간대 과거 평균에 주변 100m 가우시안 평활을 적용한 베이스라인**이다. 주변 정보가 없는 단순 과거 평균만을 비교 대상으로 사용했다고 쓰지 않는다.

| 지표                   | 베이스라인 |  LightGBM |                    비율 차이 |
| ---------------------- | ---------: | --------: | ---------------------------: |
| **상위 10% 칸 포착률** |      75.5% | **94.8%** |                  **+19.3%p** |
| 상위 5% 칸 포착률      |      70.5% | **90.6%** |                  **+20.1%p** |
| 건수 예측 개선율       |       9.8% | **58.7%** | 각 수치 자체를 개선율로 표기 |

포착률 차이는 발표에서 `%p`를 우선 사용한다. 상대 개선율을 사용할 경우 기준과 계산 방식을 함께 밝힌다.

| 지표            | 변화          | 상대 개선율 |
| --------------- | ------------- | ----------: |
| 상위 10% 포착률 | 75.5% → 94.8% |   약 +25.6% |
| 상위 5% 포착률  | 70.5% → 90.6% |   약 +28.5% |

상위 10% 기준으로 미포착 신고 비중은 **24.5% → 5.2%**다. `놓치는 신고 비중이 약 4.7분의 1로 줄었다`, `약 4건 중 1건을 놓치던 수준에서 약 20건 중 1건을 놓치는 수준으로 줄었다`로 설명할 수 있다. 이 역시 시민 신고의 미포착 비중이며 실제 단속의 미포착률이 아니다.

## 7. 기록이 없던 위치와 평가 보강

- 과거 기록이 없던 칸만을 따로 분리한 포착률은 측정하지 않았다.
- 테스트 기간 신고의 **99.5%**가 학습 기간인 7월까지 신고가 있던 지점의 반경 200m 안에서 발생했다.
- 나머지 **0.5%**는 평가에서 미포착으로 계산했다는 것이 백엔드 설명이다.
- 이 99.5%를 `동일한 격자 칸에 과거 신고가 있었다`는 뜻으로 바꾸지 않는다. 기존 신고 지점의 반경 200m 안이라는 공간 범위다.
- 칸 자체에는 기록이 없지만 주변 신고 덕분에 포착한 비율은 별도로 산출되지 않았다. 현재 자료만으로 그 성능을 주장하지 않는다.

백엔드는 위치가 모호한 주소 943건을 제외하고, 평가 대상 칸을 학습 기간 기준으로 다시 선정해 테스트 위치 정보가 학습에 새지 않도록 검증을 보강했다고 설명했다. 보강 전후 **상위 5% 포착률은 90.4% → 90.6%**로 유지됐다.

서비스용 예측 범위를 전체 관측 기간으로 구성한 것과, 평가 시 학습 기간만으로 대상 칸을 선정한 것을 구분한다.

## 8. 모델이 참고한 정보

| 항목                         | 백엔드 공유 중요도 |
| ---------------------------- | -----------------: |
| 해당 칸의 과거 신고 빈도     |             약 40% |
| 해당 칸의 시간대별 신고 빈도 |             약 36% |
| 요일 자체                    |            약 0.3% |

공유 설명에서는 위치와 시간대 관련 신고 빈도가 판단의 대부분을 차지했다. 위 표는 공유된 주요 항목 일부이며 전체 특성 목록은 아니다. 중요도 산출 기준은 전달되지 않았으므로 이를 개별 신고 확률이나 인과적 영향 비율로 해석하지 않는다.

발표에서는 `이 모델에서는 위치와 시간대 관련 과거 신고 정보의 중요도가 높고, 요일 자체의 중요도는 낮게 나타났습니다`로 표현한다. `요일은 신고 위험에 영향이 없다`는 일반적인 결론으로 확대하지 않는다.

## 9. 서비스에서 예측을 사용하는 방식

- 예측 범위는 전체 관측 기간에 신고가 있던 지점의 반경 200m 안에 해당하는 **37,595개 격자 칸**이다.
- 칸마다 요일 7개 × 시간대 8개를 조합한 **56개 예측값**을 계산한다.
- 전체 사전 계산 규모는 **37,595 × 56 = 2,105,320개**, 약 210만 개다.
- 앱 요청 때마다 LightGBM을 다시 실행하지 않는다. 서버는 **칸·요일·시간대**를 기준으로 미리 계산된 표에서 값을 조회한다.
- 예측 범위 밖은 `판단할 수 없음`으로 응답한다는 것이 백엔드 설명이다. 이를 신고 위험 0·안전·합법으로 표시하지 않는다.

실제 응답 필드와 앱 상태의 연결은 [API 연동 현황](03_API_연동_대기.md) 및 실제 API 계약을 따른다. 이 문서의 설명만으로 응답 필드나 오류 코드를 임의로 추가하지 않는다.

## 10. 기획과 발표에 사용할 표현

### 데이터 소개

> 2025년 1~9월 용인시 시민 신고(안전신문고·새올민원) 43,212건을 활용했습니다. 정확한 관측 기간은 2025년 1월 1일부터 9월 25일까지입니다.

### 모델 소개

> 용인시를 50m 격자로 나누고, 칸·요일·3시간대별 하루 평균 시민 신고 건수를 LightGBM 포아송 회귀로 예측했습니다. 같은 요일·시간대에서 예측값이 상위 10%인 칸을 2단계 주의 대상으로 안내합니다.

### 비교 대상 소개

> 칸×요일×시간대 과거 평균에 주변 100m 평활을 적용한 베이스라인과 비교했습니다.

### 성능 소개

> 시간 순서로 분리한 2025년 8월 1일~9월 25일 테스트에서, 위험 상위 10% 칸의 시민 신고 포착률이 75.5%에서 94.8%로 19.3%p 높아졌습니다.

### 실행 방식 소개

> 예측값을 미리 계산해 두고 서버가 위치·요일·시간대에 맞는 결과를 조회하므로, 앱 요청마다 모델을 실행하지 않습니다.

### 용어 기준

| 사용 권장                                      | 피할 표현과 이유                                                      |
| ---------------------------------------------- | --------------------------------------------------------------------- |
| 시민 신고 위험, 신고 집중 구역, 신고 다발 지점 | `실제 단속을 예측했다`: 학습 목표와 다름                              |

## 11. 확인 사항과 검증 범위

### 좌표 변환 단계 5건 불일치

전달된 제외 건수대로 계산하면 다음과 같다.

```text
44,665 - 394 - 943 = 43,328
백엔드 전달 좌표 변환 성공 건수 = 43,323
차이 = 5건
```

추가 제외 5건이 있는지, 단계별 수치 중 정정이 필요한지 원인은 확인되지 않았다. 이 문서에서는 전달값 43,323건을 임의로 바꾸지 않고 확인 필요로 표시한다. 최종 모델 사용 건수 43,212건도 이 산술 차이만으로 변경하지 않는다.

### 추가로 구분할 정보

- 좌표 변환 성공 43,323건에서 최종 사용 43,212건까지는 111건 차이가 있다. 관측 기간·용인 격자 조건에 따른 제외로 설명됐지만 각각의 세부 건수는 전달되지 않았다.
- 공유된 모델 설명 본문에는 요일·시간대별 포착률을 전체 지표로 집계하는 세부 방식과 특성 중요도 산출 기준이 명시되지 않았다. 원시 평가 로그·모델 산출물을 통한 성능 재현 검증도 수행하지 않았다. 이 문서만으로 평가 수치를 재현했다고 주장하지 않는다.
- 394건·943건의 제외 조건과 집계의 정확성은 전처리 산출물로 별도 확인할 사항이다. 첨부 원본을 직접 정제하거나 좌표를 다시 조회한 결과가 아니다.
