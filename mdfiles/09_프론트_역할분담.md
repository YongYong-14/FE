# 세울까말까 — 프론트 역할 분담

기준일: 2026-11-07 · 팀원1·팀원2 기준 배분안

기능 수, 상태 처리 난이도, 기존 초기 기반의 재사용 범위, 통합 시 의존성을 고려한 임의 배분이다. 팀원 번호를 실제 개발자·개인 브랜치와 연결하지 않는다. 브랜치는 온준규 `onjunku`, 김서은 `ummpa`라는 기존 정책을 유지한다.

초기 세팅은 공통 기반으로 재사용한다.

## 1. 배분 요약

| 담당  | 중심 역할                | 주요 기능                                                                   | 작업 특성                                                    |
| ----- | ------------------------ | --------------------------------------------------------------------------- | ------------------------------------------------------------ |
| 팀원1 | 주차 판단의 핵심 진행    | 로그인·권한 안내·차량, 홈, 위치 확인, 횡단보도, 분석·리포트, 진행 복원·취소 | 화면 수보다 시간·상태·중복·취소 경계의 난이도가 높음         |
| 팀원2 | 지도 탐색·이력·후속 이용 | 지도·검색, 주변 주차장, 기록·상세, 마이페이지, 사후 설문, 데모 설정 UI      | 화면·필터·저장 데이터 표시의 양이 많고 여러 기능 연결이 필요 |

주차 타이머·확정·횡단보도·분석·취소·복원은 하나의 상태 흐름이므로 팀원1이 함께 담당한다. 팀원2에는 목록·지도·필터·기록·설문을 묶어 화면과 데이터 처리 작업량을 배분한다. 초기 기반이 있는 로그인·차량·5탭은 다시 만드는 작업이 아니라 기획·Figma에 맞춰 완성하는 작업이다.

실제 작업 시간의 확정 견적은 아니다. 개별 화면의 Figma 정밀 검토와 첫 통합 결과에 따라 부담이 큰 보조 화면·스타일 작업을 조정한다. 핵심 주차 상태를 둘로 나눠 관리하는 방식은 사용하지 않는다.

| 홈               | 차량·권한 상태, 최근 주차 요약, 확인 진입·이어가기                         | 중간      |

### 주요 소유 경로

- `src/features/auth/`, `src/features/vehicle/`, `src/features/home/`, `src/features/parking/`
- 로그인·차량·위치·분석에 해당하는 `src/services/demo/`·`fixtures/` 모듈
- 주차 진행 상태의 저장·복원 모듈과 세션 저장
- `src/providers/`와 루트·초기 진입·주차 경로의 통합

### 제공할 공개 기능

- 현재 주차 단계·선택 위치·분석 결과와 진행 여부.
- 위치 확인 시작·확정·재측정·연장·횡단보도 응답·재연결 취소의 동작.
- 기존 기록의 재분석 진입 및 취소·동일 기록 갱신 동작.
- 현재 결과와 기록 상세가 함께 사용할 리포트 표시 컴포넌트.
- 사후 설문이 참고할 차량 재연결·진행 중 주차 상태.
- 데모 설정 UI에서 호출할 주차·기기 시나리오 제어와 전체 초기화 동작.

- `src/features/map/`, `parking-lots/`, `history/`, `settings/`, `survey/`, `demo/`

- 사후 설문 표시·응답/건너뛰기 보관과 재노출 방지.
- 공통 동작을 호출하는 데모 설정·초기화 확인·탈퇴 확인 UI.

## 4. 공통 파일과 연결 지점

| 대상                          | 주 담당               | 연결 규칙                                                                                 |
| ----------------------------- | --------------------- | ----------------------------------------------------------------------------------------- |
| 공통 타입·주차 단계·결과 상태 | 팀원1                 | 기존 `shared/types`를 기준으로 필요한 리포트 자료형을 작성하고 팀원2와 공유               |
| 기록·설문 보관 모듈           | 팀원2                 | `storage` 공개 함수로 제공. 주차 기능이 기록 화면의 내부 코드를 참조하지 않음             |
| 지도·좌표·검색 선택           | 팀원2                 | 기존 공통 좌표 타입 사용. 선택 변경을 전달하고 타이머는 지도 내부에 넣지 않음             |
| 리포트 표시·기록 재분석       | 팀원1                 | `features/parking`의 공개 진입점 제공. 기록 상세는 동일 결과를 표시하고 필요 시 동작 호출 |
| provider·전체 진행 우선순위   | 팀원1                 | 팀원2가 작성한 설문 provider 등을 앱 상위에 연결. 현재 주차 진행을 우선                   |
| 패키지·lockfile·앱 설정·CI    | 팀원1                 | 변경 전 공유하고 같은 PR에서 파일·lockfile 정합성 확인                                    |
| 테마·공통 UI                  | 초기 설정을 공통 사용 | 필요한 확장은 작업한 사람이 작성하고 다른 담당 화면의 영향 확인                           |
| 서비스 공개 진입점            | 팀원1 통합            | 각 담당자가 자신의 모듈 작성. 공개 export 변경은 함께 확인                                |

주 담당은 변경 충돌을 줄이기 위한 기준이다. 다른 담당자가 수정할 수 없는 파일이라는 의미는 아니다. 양쪽에서 같은 파일을 동시에 크게 바꾸는 경우 먼저 범위를 조율한다.

기록 화면에서 주차 기능을 호출하더라도 주차 기능이 다시 기록 화면을 참조하지 않게 한다. 저장 모듈은 화면을 참조하지 않고, 모의 서비스와 공통 타입도 기능 화면에 의존하지 않는다.

현재 내부 타입은 프론트 연결 기준이며 API 명세가 아니다. 실제 API·지도 SDK·GPS·블루투스 연결은 후속 범위로 유지한다.

## 5. 권장 개발 순서

1. 초기 설정을 `dev`에 공유한 뒤 두 개인 브랜치가 같은 기반을 반영한다.
2. 공통 좌표·기록·결과 자료형, 지도 선택 전달, 기록 저장·재분석의 연결 지점을 먼저 맞춘다.
3. 팀원1은 위치 확인·타이머·횡단보도·분석·취소를, 팀원2는 지도·검색·주차장·기록 표시를 우선 개발한다.
4. 분석 완료 → 기록 표시, 지도 검색 → 위치 보정, 기록 재시도 → 동일 기록 갱신을 통합한다.
5. 설문·설정·데모 메뉴·초기화·탈퇴를 연결하고 전체 시나리오를 교차 확인한다.

세부 화면 구현 전 남은 Figma 정밀 검토를 진행하고 각 담당 화면에 적용한다. 개발 단위별 PR로 `dev`에서 통합하며 모든 기능을 끝낸 뒤 한 번에 합치지 않는다.

## 6. 검증 책임

- 각 담당자는 자신의 정상·실패·빈 상태와 저장·취소 경계를 확인한다.
- 팀원1: 터치·백그라운드·완전 종료·시간 연장·재측정·모달 응답·재연결 취소와 늦은 결과 저장 방지.
- 팀원2: 지도/목록 동기화·필터·당시 상세·재시도·설문 재노출 방지·초기화 확인 UI.
- 두 담당자: 좁은 화면·확대 글자, 같은 서비스 결과·저장 상태 사용, 로그아웃 후 접근 조건, 전체 초기화 후 늦은 작업 복원 방지.
- 상대 담당자의 PR을 검토하고 `npm run check`·Android 번들 생성·필요한 기기 확인 결과를 남긴다.

현재 실제 개발자와 팀원 번호의 연결은 미정이다. 번호별 배분안을 전달할 수 있도록 구성했으며 실제 인원을 임의로 지정하지 않는다.
