# 세울까말까 — API 연동 계획

기준일: 2026-11-07 · 명세서 미수령 · 연동 대기

## 1. 연동 범위

API 명세서 수령 및 별도 연동 지시 후 실제 계약을 검토한다. 현재는 [공통 정책](00_공통정책.md)에 따라 모의 데이터·응답을 사용하며, 백엔드 자료·키·엔드포인트·일정을 요청하지 않는다.

| 구분        | 대상                                           | 후속 확인                                      |
| ----------- | ---------------------------------------------- | ---------------------------------------------- |
| 인증·계정   | 카카오 로그인, 사용자, 세션, 로그아웃·탈퇴     | SDK/API 경계, 만료·실패, 계정별 데이터 처리    |
| 차량        | 차량 1개 등록·조회·변경                        | 식별 정보, 기기 보관·서버 저장 책임            |
| 주차 이벤트 | 연결 해제·재연결, 위치·주차 시각·횡단보도 응답 | 이벤트 ID, 중복 방지, 확정 시점·시간 기준      |
| 위험 분석   | 요청·진행·완료·정보 부족·실패                  | 상태 매핑, 근거·출처, 취소·늦은 응답           |
| 리포트      | 금지 구역, 신고·단속 이력, 시간대, AI 결과     | 제공 항목, 누락 값, 거리·과태료·통계의 근거    |
| 지도        | 구역·핀·신고 건수·검색·주소 변환               | 데이터 공급자, 좌표 체계, 지도 SDK와 서버 책임 |
| 주변 주차장 | 위치·거리·요금·운영 상태·유형                  | 반경·필터·정렬 지원, 갱신 기준                 |
| 기록        | 저장·조회·상세·재시도                          | 보관·삭제·페이지 처리, 과거 시점 재분석 범위   |
| 설정·설문   | 사후 설문 ON/OFF, 대상·응답·건너뛰기           | 설정 유지, 주차별 중복 노출·제출 방지          |

알림 발송·알림 토큰·위험/야간 알림 설정은 연동 범위에 포함하지 않는다.

## 2. Android 기기 기능·외부 SDK

다음 항목은 서버 API 응답 교체와 구분한다.

| 대상          | 연결·검증 내용                                                           |
| ------------- | ------------------------------------------------------------------------ |
| 블루투스      | 기기 조회·등록 식별, 연결 해제·재연결 이벤트, 백그라운드 수신·복원       |
| GPS·권한      | Android 권한·설정 복귀, 좌표·정확도 제공 여부, 조회 실패, 사용자 보정    |
| 지원 지역     | 용인시 행정구역 판별과 수정·수동 지정 좌표 검증                          |
| 지도          | 공급자·React Native 연동 방식, SDK 초기화, 마커·구역, 카메라·조작 이벤트 |
| 검색·주소     | 장소 검색·주소 변환의 제공 주체와 좌표 전달                              |
| 시간·수명주기 | 잠금·백그라운드·프로세스 종료·재부팅·시간 변경 시 상태 일관성            |

지도 공급자·연동 라이브러리와 실제 백그라운드 실행 방식은 미정이다. 위치 정확도 값은 제공 여부·단위를 확인하며 실제 오차의 확정값으로 취급하지 않는다. 현재 기획의 정확도별 자동 확정 차단 없음 정책은 유지한다. 참고: [Android 위치 정확도 문서](<https://developer.android.com/reference/android/location/Location#getAccuracy()>).

## 3. 데모 교체 기준

- 화면·탐색·입력·타이머·게이지·모달과 실제 조회·제출 처리를 분리한다.
- 내부 데모 자료형은 API 계약이 아니다. 명세에 맞춰 변환 계층·저장 책임을 정한다.
- 실제 연동 경로의 고정 응답·가짜 지연·실패 주입·시연 제어를 제거·교체한다.
- 데모 데이터가 실제 계정·실제 기록에 섞이지 않도록 구분한다.
- 현재 로컬 저장을 실제 인증·서버 저장 계약으로 간주하지 않는다.
- 지도 교체 시 공통 UI·좌표 모델은 재사용하고 SDK 렌더링·제스처·GPS·검색은 연결·조정한다. 전체 재사용이나 작업량 감소를 보장하지 않는다.
- 실제 응답·권한·실패 조건에 맞춰 화면과 상태 처리를 재검증한다.

## 4. 명세 대조 체크리스트

- [ ] 인증·세션 만료·로그아웃·탈퇴·캐시와 계정별 복원 정책
- [ ] 좌표 체계, 거리·금액 단위, 주차 시각·날짜·시간대
- [ ] 필수·선택·null·누락 값과 UI 미제공 처리
- [ ] 1단계·2단계·확인된 위험 없음·정보 부족·분석 실패의 서버 상태 매핑
- [ ] 기록 6개 필터, 정렬·페이지 처리·조회 범위
- [ ] 이벤트·리포트 연결과 중복 요청·중복 기록 방지
- [ ] 정보 부족·분석 실패의 보관 및 동일 기록 재시도
- [ ] 과거 기록 재분석 가능 여부·요청 시점·원래 주차 시각 유지
- [ ] 완료 전 재연결의 요청 취소·늦은 응답·서버 저장 제어
- [ ] 사후 설문 응답·건너뛰기·재노출 방지와 설정 유지
- [ ] 실제 계정 삭제·카카오 연결 해제·서버 데이터 삭제 책임
- [ ] 실제 데이터의 출처·법정 기준·운영 정보 갱신 여부
- [ ] 데모 경로 교체 후 화면별 로딩·오류·재시도·기기 동작 검증

UI 문구를 API 파라미터나 응답값으로 임의 확정하지 않는다. 설문 건너뛰기도 임의의 단속 응답값으로 제출하지 않는다.
