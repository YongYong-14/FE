# 세울까말까 — API 연동 현황

기준일: 2026-11-09 · 기준 명세: API 명세 v0.11 (ERD v5.1) · 백엔드 저장소 `YongYong-14/BE` 응답 레코드와 대조

## 1. 실행 설정

서버 API만 사용한다. `.env.example`을 복사한 `.env`에 서버 주소와 카카오 네이티브 앱 키를 설정한다. 서버 주소가 비어 있으면 설정 오류를 표시한다. 수동 사용자 액세스 토큰 우회·로컬 목 서버·웹 모의 로그인은 제공하지 않는다.

Android 카카오 SDK의 사용자 토큰을 `POST /auth/kakao`에 전달하고 응답의 서비스 JWT를 저장·갱신한다. SDK 키 변경 후에는 `npm run prebuild:android`와 `npm run android:device`로 다시 빌드한다. 로그인 취소 시 백엔드는 호출하지 않는다. 웹 실제 인증은 구현하지 않았다.

## 2. 엔드포인트와 앱 연결 지점

| API                         | 앱에서 부르는 곳                          | 비고                                                                                                         |
| --------------------------- | ----------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| POST /auth/kakao            | 로그인 화면 → `accountService.signIn`     | 토큰 저장, 미동의 약관으로 동의 화면 이동                                                                    |
| POST /auth/refresh          | `services/api/client.ts` 자동             | 만료 30초 전·401 TOKEN_EXPIRED에서 한 번만(동시 요청 합침)                                                   |
| POST /auth/logout           | 마이페이지 로그아웃                       | 실패해도 기기 로그인은 끝낸다                                                                                |
| GET /me                     | 앱 시작 시 로그인 복원                    | 약관 최신 이력으로 미동의 판단                                                                               |
| POST /me/agreements         | 약관 동의 화면(`(onboarding)/agreements`) | TERMS·PRIVACY·LOCATION_SERVICE, 버전 `2026-11-06-v1`                                                         |
| DELETE /me                  | 마이페이지 회원 탈퇴                      | 성공한 뒤에만 기기 데이터 삭제                                                                               |
| POST /webhooks/kakao/unlink | 앱은 호출하지 않음                        | 카카오 서버 전용                                                                                             |
| GET /vehicle                | 로그인·복원, 홈 진입                      | 서버에 차량이 없으면 차량 등록으로 이동                                                                      |
| PUT /vehicle                | 차량 등록·변경                            | 페어링 기기의 이름·MAC·종류. 409면 다시 조회 후 1회 재시도                                                   |
| POST /parking-events        | 위치 확정 → 횡단보도 응답 뒤              | 아래 3절                                                                                                     |
| GET /parking-events/latest  | 홈                                        | 최근 주차·신고 데이터 기간(dataPeriod)                                                                       |
| GET /parking-events         | 기록 탭, 홈                               | 1단계·2단계 필터는 `level`, 나머지는 앱이 거름                                                               |
| GET /parking-events/{id}    | 결과·기록 상세                            | 근거·신고 집중 시간(peak). 주소는 3초 뒤 한 번 더 읽음                                                       |
| GET /parking-lots/nearby    | 주변 주차장 탭                            | 최근 주차 위치(없으면 현재 위치) 기준, 자동 1km 확장 안내                                                    |
| GET /map/risk-zones         | 지도 탭                                   | 보이는 범위를 약 1.8km 고정 칸으로 나눠 조회(한 변 2km 제한), 이동·확대 후 0.25초 뒤 새 칸만 요청, 10분 캐시 |
| GET /health                 | 서버 상태 점검용 서비스                   |                                                                                                              |

코드 위치: 요청·응답 자료형 `src/services/api/types.ts`, 엔드포인트 `endpoints.ts`, 공통 요청·토큰 `client.ts`, 응답 변환·화면 문구 `mappers.ts`, 기능별 구현 `services.ts`.

## 3. 주차 판정 흐름

- 앱이 `clientEventId`(UUID)를 만들고 제출값 전체를 진행 상태에 저장한다. 재시도·앱 재실행 뒤에도 같은 값으로 보낸다.
- 횡단보도 응답은 앱 안에서만 쓰고 요청에 넣지 않는다(서버는 모르는 필드를 400으로 거절).
- 횡단보도 `예`는 직접 응답을 근거로 앱 리포트·기록을 1단계로 표시한다. 원래 서버 결과(`serverReport`)와 응답은 기기에만 보관하고 서버 판정·측정값과 구분한다. 서버가 이미 1단계면 원래 시설 근거를 유지한다. `아니요`는 서버 판정을 유지한다.
- GPS 정확도: 15m 이내만 15초 자동 확정(AUTO), 15~50m는 직접 확정(CONFIRMED·ADJUSTED), 50m 초과는 GPS를 쓰지 않고 위치를 직접 고른다.
- 확정 위치가 GPS에서 200m를 넘으면 앱이 먼저 막고, 서버가 400 ADJUST_DISTANCE_EXCEEDED·AUTO_CONFIRM_NOT_ALLOWED를 주면 위치 확인으로 되돌린다.
- 판정 FAILED(1회)는 같은 키로 한 번 자동 재전송한다. 2회째도 FAILED면 기록만 남긴다.
- 409 IDEMPOTENCY_KEY_REUSED는 새 키로 한 번 다시 보낸다. 403 LOCATION_CONSENT_REQUIRED는 동의 화면으로 보내고 동의 후 같은 요청을 이어서 보낸다. 404 VEHICLE_NOT_FOUND는 차량 다시 등록을 안내한다.
- 네트워크·서버 오류는 기록을 만들지 않고 "다시 시도"를 보여준다. 같은 키라 중복 저장되지 않는다.
- 결과 표시: SUCCEEDED 1·2단계, 명확한 3단계만 "위험 정보 없음", 단계 누락·미지원 값과 PARTIAL은 "판단 불가"로 보여주고 "안전"이라고 쓰지 않는다.
- 알림 기능은 제외한다. 응답의 `notify`는 사용하지 않으며 알림 설정·delivery API를 호출하지 않는다. 실패 결과도 알림 없이 처리한다는 표현 대신 기록 보관 여부를 설명한다.

## 3-1. 기기 저장

- 서비스 토큰은 AsyncStorage(`auth-tokens`)에 둔다. 운영 전에는 OS 보호 저장소(expo-secure-store, 새 개발 빌드 필요)로 옮긴다.
- 서버 목록은 최대 100건이고 페이지·커서 항목이 없다. 기기에는 횡단보도 응답·원래 제출값을 함께 보관하고 서버 목록과 id로 병합한다. 응답에 없다는 이유로 보관 기록을 삭제하지 않으며 1·2단계 필터도 보관 기록을 함께 조회한다. 다른 기기에서 서버의 100건 이전 전체 기록을 받는 기능은 후속 서버 명세가 필요하다.
- 결과 재조회·재분석 시 횡단보도 응답을 다시 반영하고, 1·2단계 필터에도 앱에서 적용한 분류를 쓴다. 응답은 다른 기기·앱 데이터 삭제 후에는 복원되지 않는다. 기기 간 동기화는 추후 서버 명세에 응답 저장 항목이 추가될 때 연결한다.
- 탈퇴 후에는 토큰·기록·진행 상태·이전 버전 알림 표시 기록을 모두 지운다.

## 3-2. 지도 탭

- Android 지도 탭은 카카오 지도 SDK(`@react-native-kakao/map`)를 쓴다. `EXPO_PUBLIC_KAKAO_NATIVE_APP_KEY`를 그대로 쓰며, 카카오 개발자 콘솔에서 해당 앱의 카카오맵 사용 설정을 켜야 한다. 끌기·확대는 SDK가 처리하고, 멈추면 화면 범위를 재서 위험 구역·말풍선을 다시 그린다(움직이는 동안은 숨김). 카카오맵은 ARM 기기·에뮬레이터에서만 동작한다.
- 웹과 키·지도 모듈이 없는 빌드는 OpenStreetMap 타일(`https://tile.openstreetmap.org/{z}/{x}/{y}.png`)을 배경으로 쓰고 화면에 출처(© OpenStreetMap)를 표시한다. 다른 주소는 `EXPO_PUBLIC_MAP_TILE_URL`로 바꾼다. 공용 타일 서버는 시연·개발용이다.
- 끌어서 이동, 확대·축소 버튼, 웹 마우스 휠, 휴대폰 두 손가락 확대를 지원한다. 지도 탭과 공통 지도 확대 단계는 12~20이며, 카카오 SDK에서는 실제 지원 범위 안으로 보정한다. 넓게 축소하면 화면 중앙부터 최대 12개 조회 구간만 요청하고 신고 건수 말풍선은 숨기며 확대 안내를 표시한다.
- 위험 구역은 보이는 범위를 약 1.8km 고정 칸으로 나눠 `GET /map/risk-zones`로 받는다. 같은 칸은 10분 동안 다시 받지 않는다.
- 신고 건수 말풍선은 확대 15.5 이상에서만 보이고, 겹치면 건수가 많은 칸을 먼저 칸 위·아래에 놓고 나머지는 숨긴다.

## 4. 기기 기능·외부 연결

장소 검색은 `EXPO_PUBLIC_KAKAO_REST_API_KEY`로 카카오 `GET /v2/local/search/keyword.json`과 `GET /v2/local/search/address.json`을 직접 호출한다. 인증은 `KakaoAK`이며 서비스 JWT·카카오 사용자 토큰을 보내지 않는다. 용인시 범위 키워드 검색과 일반 검색을 합쳐 같은 장소 ID를 제거하고, 실제 주소가 용인시인 결과를 우선해 최대 10개 표시한다. 도로명 주소가 없으면 지번 주소를 사용하며 `x`는 경도, `y`는 위도로 변환한다. 키가 없을 때만 Android 주소 검색으로 대체하고 카카오 호출 실패를 기기 검색으로 숨기지 않는다. 검색어 변경·화면 이탈 시 이전 HTTP 요청을 취소하며 응답 대기는 8초로 제한한다. 유효한 검색 결과 없이 일부 호출이 실패하면 빈 결과 대신 재시도 상태를 표시한다.

Android 실제 페어링·GPS·권한은 [실기기 블루투스와 GPS](11_실기기_블루투스와_GPS.md)를, 온보딩과 주소 검색·공유·실제 지도 적용 및 미제공 기능은 [실서비스 실행 기준](12_온보딩과_실서비스_전환.md)을 따른다. 서버의 `lastKnownLocation` 별도 전송은 연결하지 않았고 알림 기능은 제공하지 않는다.
